# Тест-кейсы: формат и написание

## Формат YAML

```yaml
id: tc_01                              # Уникальный идентификатор
name: "Успешный вход — стандартный пользователь"   # Название
description: >                          # Описание (может быть многострочным)
  Пользователь с корректными учётными данными
  попадает на страницу каталога.
start_url: "https://www.saucedemo.com/" # URL для открытия браузера
severity: critical                      # critical | high | medium | low
tags: [авторизация, smoke, saucedemo]  # Теги для Allure

steps:
  - step: "Описание действия на естественном языке"
    expected: "Что должно произойти"

  - step: "Второй шаг"
    expected: "Ожидаемый результат второго шага"
```

## Опциональные поля

```yaml
preconditions:
  - "Аккаунт testuser@test.com уже создан"
  - "Пользователь не авторизован"
```

## Принципы написания хороших шагов

### 1. Конкретность, а не расплывчатость

```yaml
# Плохо — слишком общо
- step: "Войти в систему"
  expected: "Вход успешен"

# Хорошо — конкретно
- step: "Войти под 'standard_user' / 'secret_sauce', нажать Login"
  expected: "Открывается страница Products с URL /inventory.html"
```

### 2. Один шаг — одно логическое действие

```yaml
# Плохо — слишком много в одном шаге
- step: "Войти, найти товар, добавить в корзину, оформить заказ"
  expected: "Заказ оформлен"

# Хорошо — разбито по смыслу
- step: "Войти как 'standard_user' / 'secret_sauce'"
  expected: "Страница Products открыта"

- step: "Нажать 'Add to cart' на «Sauce Labs Backpack»"
  expected: "Кнопка изменилась на «Remove», счётчик корзины показывает «1»"
```

### 3. Expected result должен быть верифицируемым

```yaml
# Плохо — нельзя проверить
  expected: "Работает корректно"

# Хорошо — конкретный текст или элемент
  expected: "Красный баннер с текстом «Username and password do not match...»"
```

### 4. Указывайте конкретные данные

```yaml
# Плохо — агент не знает что вводить
- step: "Заполнить форму регистрации"

# Хорошо
- step: "Ввести имя 'TestUser', email 'test@example.com', пароль 'Test@1234'"
```

### 5. Тест-кейс с заведомым багом

Для проверки что система находит баги — пишите expected result согласно **правильному поведению**, даже если сайт его нарушает:

```yaml
# Система войдёт как problem_user, кнопка НЕ изменится → баг зафиксирован
- step: "Войти как 'problem_user', нажать 'Add to cart' на «Sauce Labs Backpack»"
  expected: "Кнопка меняется на «Remove», счётчик корзины показывает «1»"
```

### Как добавить новый тест-кейс

1. Создайте файл `test_cases/{сайт}/tc_XX_{название}.yaml`
2. Заполните поля согласно формату
3. Запустите: `python run_tests.py test_cases/{сайт}/tc_XX.yaml`
4. Нет никаких дополнительных регистраций — система автоматически подхватит новый файл
